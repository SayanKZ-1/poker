# Границы защиты 0.4.2

Сервер раздаёт карты криптографическим Fisher–Yates с rejection sampling; клиент не задаёт колоду. Приватное состояние хранится в схеме private. Клиент получает только разрешённые ему карты. RLS на svoi_views фильтрует по проверенному auth.uid(), прямые записи запрещены.

Команда обрабатывается внутри транзакции с блокировкой строки комнаты. Ключ actor_id + request_id и отпечаток payload защищают повторные запросы. Повтор одобрения докупки не должен создавать второе начисление; изменённый payload с тем же ID отклоняется. HTTP topUp сохраняется только как совместимое имя запроса, а не прямой выдачи фишек. Решения и управление паузой закупа доступны только хозяину.

Сумма фишек ограничена техническим бюджетом 10^15 для всего стола; арифметика банков целочисленная, проверка сохранения суммы использует BigInt. Подтверждённая докупка во время руки не входит в её ставки, банки или расчёт результата.

Окно администратора замораживает дедлайн и автораздачу. В базе сохраняется срок паузы; worker снимает её при потере связи. Старый идентификатор окна не может снять новую паузу. Ранее запрошенная обычная пауза стола сохраняется.

Локальный гостевой сервер привязан к loopback. Облачный клиент использует Supabase anonymous Auth: очистка браузерного хранилища/переход на другое устройство создаёт другую личность; восстановления аккаунта по одному нику нет.

Администратор инфраструктуры имеет технический доступ к базе и коду. Независимый аудит, нагрузочная проверка и реальное облачное подключение не выполнены. Новые проверки в этой поставке не запускались по просьбе владельца.
