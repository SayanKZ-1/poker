# СВОИ — закрытый покер для друзей, 0.3.0

No-limit Texas Hold’em, 2–6 игроков, условные фишки. Локальное демо и Node.js-сервер закрытых Telegram Mini App комнат. Это тестовый проект, не опубликованный или сертифицированный покер-рум. Денежных платежей, призов, кассы и вывода фишек нет.

## Быстрый запуск

Нужен Node.js 22+. Внешних npm-зависимостей нет, `npm install` не требуется.

```bash
cd svoi-poker
npm test
npm start
```

Откройте `http://localhost:3000`. В режиме разработки сервер доступен только на loopback. Для проверки нескольких игроков откройте независимые браузерные профили/контексты. Хозяин создаёт комнату, копирует приглашение, гости запрашивают вход, хозяин подтверждает заявки.

Автономное демо: откройте `svoi-preview.html` в браузере и нажмите «Начать демо». Вы играете с пятью локальными ботами, друзья к одному HTML не подключаются. Пересборка после изменения исходников:

```bash
npm run preview:build
```

## Автоматическая игра

Хозяин нажимает «Начать игру» только один раз. Дальше сервер начинает следующую раздачу через 6 секунд после выплаты, с точностью своего тика 500 мс. Работа не зависит от открытого экрана хозяина. Демо использует ту же логику с тиком 250 мс.

Не сделал ход вовремя — пас и «Не играю», в том числе при бесплатном чеке (выбранное домашнее правило). Можно заранее нажать «Не играю». Ручной автопас выполняется только в собственную очередь; уже сделанный олл-ин остаётся в розыгрыше. «Я вернулся» относится только к будущей руке, не отменяет текущий пас. Переподключение само по себе не возвращает неактивное место в игру.

В кэше неактивные не получают новых карт; после пропуска рук/позднего входа возвращаются на BB. Когда готовых меньше двух, автораздача ждёт. В турнире неактивные продолжают платить обязательные блайнды и автоматически пасуют; страдла нет. Подробности и исключения возобновления heads-up: `RULES.md`.

Хозяин может поставить общий стол на паузу после текущей руки и возобновить игру. Последняя завершённая раздача доступна для разбора и экспорта во время следующей. Данные лежат в памяти, не переживают перезапуск.

## Подключение Telegram

1. Создайте бота в @BotFather и настройте Main Mini App с HTTPS-адресом приложения.
2. Разместите Node.js-процесс на хостинге, поддерживающем долгоживущий процесс и SSE. В этой версии нужен **один** экземпляр: память между процессами не разделяется.
3. Задайте в секретах хостинга (не в клиентском коде):

```dotenv
NODE_ENV=production
AUTH_MODE=telegram
HOST=0.0.0.0
PORT=3000
PUBLIC_ORIGIN=https://YOUR-DOMAIN
BOT_USERNAME=YOUR_BOT_USERNAME
BOT_TOKEN=YOUR_SECRET_BOT_TOKEN
ALLOWED_TELEGRAM_IDS=123456789,987654321
```

Не отправляйте BOT_TOKEN в переписку, не публикуйте `.env` и не добавляйте его в репозиторий. Для первого дружеского теста заполните список ALLOWED_TELEGRAM_IDS. Дополнительно действуют приглашения и подтверждение каждого гостя хозяином комнаты.

Настройте HTTPS и проксирование SSE без буферизации; пример `deploy/nginx-location.conf`. Сверяйте условия/лимиты выбранного хостинга. Сервер проверяет Telegram initData, сроки, права и допустимые команды. В публичном окружении dev-аутентификация запрещена.

Официальная документация: https://core.telegram.org/bots/webapps

## Структура и проверка

- `lib/poker.mjs`: правила, карты, банки, участие и автоматический жизненный цикл.
- `server.mjs`: HTTP/SSE, авторизация, комнаты, команды и серверный тик.
- `public/`: интерфейс и локальное демо.
- `test/`: 73 автоматических теста.
- `RULES.md`, `SECURITY.md`, `VALIDATION.md`: точный поддерживаемый профиль, ограничения и фактические проверки.

Краткие HTTP-команды управления: `start`, `sitOut`, `returnToPlay`, `pause` с булевым `paused`. Клиент указывает текущие `handId`, `version` и уникальный `requestId`. Возврат и sit-out всегда относятся к авторизованному игроку; start/pause — только к хозяину. Один start не нужен для каждой руки. `/api/room` и `/api/events` возвращают персонально отфильтрованные снимки, включая `running`, `paused`, `nextHandAt`, `sittingOut`, `returnPending`, `lastHand`.

## Перед постоянным или коммерческим использованием

Нужны БД и восстановление раздачи, резервные копии, тесты настоящих Telegram-клиентов и нескольких устройств, независимый аудит правил и безопасности, проверка ГСЧ и операционного доступа. Криптографическое перемешивание не доказывает честность администратора сервера и не исключает сговор. Тесты не являются гарантией отсутствия ошибок.

Обновление 0.3 меняет исходники и демо. Уже развёрнутый сервер нужно обновить отдельно; этот архив не выполняет публикацию автоматически.
