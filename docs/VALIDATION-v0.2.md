# Проверка версии 0.2.0

Дата: 21 сентября 2026 года. Среда: Node.js 22.16.0. Это внутренние проверки в среде разработки, не независимый аудит и не сертификация.

## Воспроизведённая ошибка 0.1

В исходной версии все 26 тестов проходили, однако сохраняли незамеченным дефект разделения одного банка на искусственные слои по взносам сбросивших игроков.

Новый регрессионный тест разыгрывает легальную последовательность ставок с заранее заданной полной тестовой колодой. Два оставшихся игрока внесли по 200, три сбросившихся — 51, 102 и 153. На доске общий роял-флеш. Банк 706 должен разделиться 353/353. Исходник 0.1 возвращает 354/352, поскольку отдельно округляет слои 255, 204, 153 и 94. Версия 0.2 объединяет их и возвращает 353/353. Результаты: `docs/regression-before-after.json`.

Это не обязательно та самая раздача пользователя: её карты, стеки и последовательность действий не были предоставлены.

## Основной набор

`npm test`: **49 тестов, 49 успешно, 0 ошибок, 0 пропусков**. Полный вывод: `docs/test-output.txt`.

Проверяются банки, возвраты, деление нечётной фишки по позиции, разные олл-ины, исключение сбросивших из претендентов, запрет повторного расчёта, отсутствие частичного зачисления при ошибке, откат перехода, минимальный рейз и индивидуальное повторное открытие ставок. Отдельно проверены условия UTG-страдла, порядок ходов, запреты турнира, смена уровней только между руками, чемпион, dead button и отсутствие обхода блайндов через отключение.

В набор входят:

- 1 000 случайных завершённых раздач с проверкой сохранения фишек, завершения и приватности.
- 5 000 генерируемых состояний расчёта. Индивидуальные выплаты сравниваются с отдельно реализованным алгоритмом на границах взносов живых игроков, а не только по общей сумме. Это независимая реализация расчёта внутри проекта, не внешний аудитор. Для ранжирования обе стороны используют движок; его отдельная проверка описана ниже.
- 10 000 наборов из семи карт. Лучший ранг сравнивается с отдельно написанным прямым семикарточным вычислителем, отличным от перебора пятёрок.
- Проверки rejection sampling, допустимых границ и остановки при отсутствующей криптографической случайности без fallback на Math.random.

## Исчерпывающий перебор пятёрок

`npm run test:exhaustive` фактически перебрал **2 598 960** уникальных пятикарточных наборов. Число результатов каждой категории совпало с ожидаемыми комбинаторными величинами. Отчёт: `docs/exhaustive-five.json`.

Это исчерпывающая проверка ЧИСЛЕННОСТИ КАТЕГОРИЙ пятёрок, не доказательство правильности каждого кикера, каждого семикарточного результата, всех возможных ставок или честности ГСЧ. Скрипт можно запустить повторно.

## Авторизация и HTTP/SSE

Тесты HMAC используют синтетический токен и initData. Проверяют подпись, подмену, неверный токен, свежесть, дату в будущем, дополнительное signature и повтор параметров. Настоящий бот не подключался.

Серверные тесты запускают реальный локальный Node.js-процесс и обращаются к HTTP API/SSE напрямую: приватные комнаты, одобрение, запрет доступа, персональные карты, ход, повтор/устаревание команды, переподключение, отзыв приглашения и завершение. Добавлены проверки подставленных deck/stack, повторного requestId с другим телом, турнирных запретов и безопасных полей расчёта. Это реальные сетевые запросы тестового клиента, но не браузерный Telegram E2E.

## Браузер

Автономный HTML загружен в Chromium через Playwright `set_content`. Проверены запуск настоящего локального демо и 12 закрытых карт на столе, отсутствие горизонтального переполнения на 390 px, запрет изменения страдла после раздачи, переключение в турнир без страдла.

Для экрана выплат применён явно обозначенный тестовый сценарий в памяти браузера: взносы 100/300/500, основной банк 300, побочный 400, возврат 200, итоги +200/+100/−300. Он проверяет отображение расчёта, а не является настоящей сетевой игрой. Тестовый hook не включён в распространяемые HTML/JS. Экспорт JSON действительно сохранён, проверено отсутствие deck и токена. Настольный экран проверен на 1440 px. JavaScript-ошибок в этих сценариях не обнаружено.

Отчёт: `docs/browser-report.json`. Скриншоты: `mobile-preview.png` — локальное демо, `settlement-mobile.png` и `desktop-preview.png` — явно обозначенный тестовый сценарий выплат. `docs/example-hand.json` — его пример отчёта, не реальная раздача пользователя.

Прямой переход браузера на localhost блокируется политикой среды. Agent-browser CLI оказался недоступен; проверка выполнена Playwright. Ограничения не обходились. Поэтому не заявляется браузерная онлайн-проверка сервера.

## Не проверено / не реализовано

Настоящие Telegram-клиенты и действующий бот; сетевой браузерный сценарий на нескольких устройствах; публикация, TLS, reverse proxy, контейнерная сборка; восстановление после аварии; база данных; нагрузка нескольких столов; независимый аудит правил, ГСЧ и безопасности; противодействие недобросовестному серверному администратору и сговору. Перебор пятёрок и 49 тестов не закрывают эти пункты.
