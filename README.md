# СВОИ · PWA 0.4.2

Закрытый Texas Hold’em на бесплатные условные фишки. Telegram не требуется.

## Запуск для собственной проверки

Нужен Node.js 22 или новее. В папке проекта:

```sh
npm ci
npm start
```

Открыть http://localhost:3000. Для второго независимого игрока открыть приватное окно браузера либо http://127.0.0.1:3000. Войти по коду. Хозяин открывает «Запросы на закуп», подтверждает свой стартовый бай-ин и бай-ин друга, затем закрывает окно и запускает игру. Локальный сервер доступен только на этом компьютере. Для телефонов через интернет необходима публикация PWA и подключение Supabase.

Комнаты, сессии, колода, текущая рука, запросы докупки, паузы и история команд сохраняются в `data/`. Не удаляйте эту папку для продолжения прежней игры. При обновлении остановите старый сервер и запустите новый. Одинаковая папка `data/` предназначена только для одного локального процесса.

## Закуп в Cash и Tournament

- Кнопка «Запросить закуп» доступна во время игры, в том числе после олл-ина.
- Сумма не ограничена первоначальным buy-in, остатком стека или числом предыдущих докупок. Один игрок может иметь один необработанный запрос; его можно отменить и подать заново.
- Администратор — хозяин комнаты. У него появляется окно-уведомление со списком игроков и суммами. Открытие запросов приостанавливает текущую руку и сохраняет оставшееся время хода.
- За столом отображается «Закуп в игре» и имена игроков. Хозяин подтверждает или отклоняет каждый запрос, включая собственный.
- «Арман докупил 5 000 фишек» попадает в историю и уведомление всем участникам.
- Если рука ещё идёт, начисление зарезервировано до её расчёта. Новые фишки доступны со следующей раздачи: ни текущая ставка, ни право на сайд-пот, ни уже сделанный олл-ин не меняются.
- Между раздачами фишки зачисляются сразу. Докупка не отменяет sit-out: возвращение игрок подтверждает отдельно.
- После закрытия списка игра продолжается с оставшимся временем. Пока окно открыто и связь есть, клиент продлевает паузу. При закрытии приложения/потере связи сервер автоматически снимает её после истечения двухминутного срока; запросы остаются.
- Все закупы в Cash и Tournament подтверждает администратор: стартовый бай-ин (включая свой), ребай, аддон, реэнтри и поздний вход. При реэнтри игрок должен полностью выбыть: активный олл-ин сначала рассчитывается. Одобрение реэнтри может возобновить закончившийся турнир с сохранением уровня.

## Большие стеки

Количество фишек — целое число. Максимальная сумма за одним столом, включая подтверждённые, но ещё не введённые в игру докупки: **1 000 000 000 000 000**. Это техническая граница точного численного расчёта, а не лимит buy-in. Сохранение суммы проверяется также через BigInt. Суммы сверх границы, дроби, отрицательные и нечисловые значения отклоняются до начисления. Старый потолок конечного стека в 10 миллионов снят.

## Данные и облако

- Локально: Node.js + PGlite (встроенный Postgres с хранением на диске).
- Целевая публикация: GitHub → Cloudflare Pages (`npm run build`, папка `dist`) + Supabase Postgres, Auth, Realtime и Edge Function `game`.
- `lib/poker.mjs` — общий серверный движок; `lib/service.mjs` — команды, блокировки, журнал и права владельца.
- `db/schema.sql` — таблицы, `db/supabase.sql` — запреты доступа и разрешение только собственного безопасного снимка.
- `db/worker.sql` — серверный запуск просроченных таймеров через Cron и Edge Function. Без него облачные таймеры не автономны.
- `npm run build` синхронизирует общий исходник в `supabase/functions/_shared/`.
- `svoi-preview.html` — отдельное демо с ботами. Оно не заменяет сервер и не предназначено для проверки согласования докупок между реальными игроками.

Рабочая облачная публикация: https://poker-9n5.pages.dev. Исходник подключён к `SayanKZ-1/poker`; новые коммиты в `main` автоматически собираются Cloudflare Pages. Supabase-проект подключён, схема и Edge Function `game` развёрнуты. Секретные ключи, строку подключения и пароли не размещать в клиенте, репозитории или переписке.

## Единое подтверждение в 0.4.2
При создании комнаты хозяин занимает место с нулём фишек. Его стартовый стек — заявка, которую требуется явно подтвердить. Новые участники также ждут подтверждения бай-ина в общем окне «Закуп в игре». Вход во время раздачи не даёт карты текущей руки; одобренные фишки доступны с новой руки. Открытие окна замораживает таймер хода и турнирного уровня. Необработанные заявки сохраняются после перезапуска.

Стартовый бай-ин по-прежнему выбирается по настройкам комнаты. Последующие закупы не ограничены первоначальным buy-in или числом повторений. Технический предел — суммарно 1 000 000 000 000 000 фишек на столе: превышение отклоняется до начисления. Денежных платежей нет.

Существующие сохранённые стеки не обнуляются при обновлении. Новое обязательное подтверждение применяется к новым выдачам фишек. Локальное демо с ботами — отдельный демонстрационный режим, не серверная комната.
